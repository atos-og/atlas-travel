# Portfolio demonstration

Use the private authorized account and record only the Atlas conversation. Hide phone numbers, account menus, notifications, tokens, and unrelated chats. Do not include the competitor reference recording in the repository or the public demonstration.

## Suggested sequence

1. Open the capability menu to show what the product currently supports.
2. Submit a combined route/date/adult request and show the interpreted confirmation before searching.
3. Confirm the search, show its progress response, and select one offer from the native list.
4. Open the Google Flights button. Show the route, dates, and passenger count; explain that final prices and fare rules are confirmed with the supplier.
5. Return to Atlas and refine the total ticket budget, making clear when cached results are being filtered.
6. Compare two explicit destinations using the same dates and budget. Choose one result.
7. Build a short sightseeing draft, open its sources, remove a place, and return to the preserved flight flow.
8. Explicitly save, inspect, and delete preferences.

Use future dates at recording time. If the provider fails, show the honest failure response rather than replacing it with fabricated fares. If using the offline simulator, label it clearly: it does not query real flight prices. Sightseeing can be demonstrated offline.

## What the presentation should say

Atlas is a private portfolio prototype with real integrations and bounded capabilities. It currently covers round-trip economy flights for adults, price refinement, nearby dates, explicit destination comparison, and a small sourced sightseeing catalog. It does not sell tickets, guarantee the cheapest market fare, compare buses, or send proactive price alerts.

The implementation uses deterministic Portuguese parsing. The interface should not be described as unrestricted AI understanding. Explain its preservation of context, explicit confirmations, native WhatsApp controls, and honest treatment of missing data.
